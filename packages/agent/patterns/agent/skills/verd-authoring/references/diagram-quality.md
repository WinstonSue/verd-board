# 图表编写规范

创建或修改任何原生图表前阅读本规范，并结合所选范式说明执行。本文件是图表编写质量规则的唯一正文；这些要求属于编写指导，不代表 validate 已自动检查判断语义或全部视觉问题。

[通用内容编写规范](writing.md)

## 图表的信息价值与表达

一张图聚焦一个主要问题。绘图前依据用户问题与已确认上下文确定本图的观察视角、范围和必要对象，只纳入直接帮助解释该问题的对象、关系和说明；不因架构层或其他模板结构而补入无关内容。先有事实底稿，再画对象、真实关系和关键失败路径。单句能说明的事实不必画图；复杂内容先总览再拆独立细图，用稳定引用共享来源。箭头表达明确动作或关系，必要时配图注说明结论与读法。

按已注册的图表种类选择表达：主题层次用 Mind，依赖或重试分别用 DAG 或 process，边界用架构图，静态契约用 UML 类图，参与者交互用 UML 时序图。数据比较可用文档表格；不要把自由绘制的形状称作新增统计图表或动画能力。

数字注明单位、比较基准和证据；时间精度服从来源。方案对比保留相同尺度与结构，标出真实差异。状态和风险配文字或图例，不能只靠颜色；使用项目主题与领域配色。有效主题为经典 default、缤纷 colorful、柔和 soft、复古 retro、清新 dark，未知主题回退经典。Mind 与普通画布共用六个风格色族 series-1…6；容器使用 container，节点使用 node，根节点或强调使用 emphasis。优先保存族标识并随主题换色，只有用户明确要求时才写手动颜色。Mind 主分支循环六族，后代继承，透明子节点保持透明。线型、形状和方向服从领域语义，尤其不把 UML 的实虚线统一解释为同步或异步。

元素数量与节点字数按可读性决定，不设置固定上限；流程方向服从业务与布局。避免用缩小文字或压缩间距容纳过多信息，需要时拆图并补导航。使用现有原生布局和渲染，不复制 HTML/SVG 页面模板或网页动画脚本。

风格色的“自动”只决定从六族中选哪一族，不引入第七种风格色。普通流程任务统一使用第一族 node 档，开始和判断分别使用第二、第三族 emphasis 档；同类节点保持同色，不按节点序号或连接顺序轮换。领域默认映射由渲染器提供，通常省略 styleColor；只有需要覆盖自动选族时才保存 series-1…6。不要写入手算的浅色 hex 来模拟主题颜色，也不将预览解析出的颜色回写节点。自定义颜色按用户明确要求保留。

## 构图与阅读路径

布局偏好按图表语义取舍：语义与归属正确 → 阅读路径清楚 → 避免遮挡和歧义 → 减少无效折返 → 对齐与紧凑。后面的目标不能破坏前面的目标；不设置固定像素、全图等间距、零交叉或固定折点数等审美门槛。

- 流程图先确定正常路径、异常出口和重试回路，再排节点。正常路径优先沿清晰的主轴连续展开，跨泳道时按真实职责交接；分支围绕触发点向侧方展开，不要求所有边同向。
- 连续步骤尽量沿主轴对齐，判断与侧向处理尽量处于同一水平线或垂直线。遇到绕行时，先检查两端位置和分支安排能否合理调整，再选择端口与必要折点，避免用局部线路补偿不必要的节点错位。
- 同类节点采用相近宽度、文字层级和常规间距，高度随内容调整；保持视觉节奏，不强求所有节点同尺寸或所有间距相等。
- 泳道宽度按主干、支路、说明和连线通道所需空间分配，不强制等宽，也不为填满泳道而摊散节点。说明靠近对应主题并避开连线通道，不参与主流程排队。

维护已有图时以当前保存的人工布局和连接语义为基线，仅调整本次内容需要的范围。不要为局部改字、改色或补说明重新创建整图、重排无关节点或覆盖已有端口与路径。方向、尺寸和间距由当前图决定，不把单张示例的坐标推广成固定模板。

## 成组说明使用卡片

停止条件、预算、补偿、清理、流程边界等成组多行说明默认使用真实 card；图标题、短标签和短图注可保留文本。卡片使用块级标题与正文，外观跟随主题，默认取第一族 container 档并保持不透明。卡片属于画布，不加入流程 memberIds、架构层成员或业务连线，也不作为业务步骤参加自动排队。

将旧文本转换为卡片时，保留节点身份、全部事实和必要强调，使用 cell.set 替换原节点；先通过 describe 确认当前 schema。清除旧文本的 fill:none、strokeColor:none 和 strokeWidth:0，恢复主题填充、主题描边及正常线宽；保留用户明确设置的自定义颜色。标题和段落结构与 plainText 同步。

卡片有实体底色、边框和内边距，原透明文本的位置不一定继续合适。转换后检查文字区容量及卡片与节点、箭头、标签和回路线的完整边界，需要时局部移动或扩展画布，不通过缩小文字掩盖遮挡。

## 判断节点：默认单一条件

每个菱形默认只表达一个可独立判断的条件。不同失败条件需要不同处理时必须拆分；每条出边写明判断结果及其去向。不能仅凭文案中出现“且／或”机械判断是否违规，应检查实际条件和分支语义。

反例：“输入有效且可执行？”把有效性和可执行性合并，读者无法从“否”区分输入错误还是执行条件不足。

拆分正例：先判断“输入有效？”，“否”进入“补正输入”，“是”进入“可以执行？”；第二个判断的“否”进入“补齐执行条件”，“是”进入“执行任务”。保留两种失败处理及其先后关系。

## 允许合并的有限例外

只有已有明确的统一业务定义、所有失败条件处理相同且拆分没有阅读价值时，才允许保留复合判断。必须在配套说明中写明业务定义与保留理由；不得为简化图面自行发明业务门槛。

允许合并的例子：业务已把“凭证有效”定义为“签名正确且未过期”，所有失败统一进入“重新登录”，本图只说明登录接入且不展开认证机制时，可以保留“凭证有效？”。配套说明注明：沿用业务定义，两类失败统一重新登录，拆分不增加本图所需信息。若需要分别续期和处理签名异常，则必须拆分。

## 文字与形状适配

文字必须完整容纳在形状实际可用的文字区内，并保留清晰留白。菱形等形状的文字区小于外接矩形，不能仅看外框尺寸估算容量。禁止顶部或底部裁切、水平越界、压边，以及不自然的孤字换行。

在保持含义完整的前提下先精简节点文案，详细说明移到注释或配套文档；再调整容器宽高并复核周边节点、连线和标签。保持正常可读字号，不得通过缩小字号掩盖容器不足，也不能只插入换行而不确认剩余高度。

## 交付前检查闭环

语义自查：逐一确认判断条件、失败处理和出边含义；保留复合判断时确认满足例外要求并已记录理由。

预览图的用途与保存位置遵循[通用内容编写规范](writing.md#交付与自查)：默认写入最终工作区之外的临时目录，仅用于自查和按需对话确认，不复制为正式工作区内容；最终保留原生源文件。用户明确要求导出图片时，按要求保存导出文件。

对当前计划执行 validate，再对每张受影响的图执行 preview，并打开生成图片检查：

- 缩略看整体：主要阅读路径、分组与职责边界是否容易识别，留白是否服务于分组与连线；流程图另检查异常出口、终点、跨泳道交接与返回路径是否容易追踪。
- 放大看局部：受影响节点及周边的文字是否完整、换行是否自然、留白是否清晰；复核端口、转角、交叉和标签，确认连线与标签没有遮挡或穿过节点，也没有产生错误汇合的视觉暗示。
- 沿线读流程：从入口沿正常路径读到终点，再逐条追踪结果分支、异常出口和回路，确认标签对应唯一明确的去向、汇合关系真实、返回目标与重新触发条件清楚；说明卡片不遮挡这些路径。现有人工图也按同样标准检查，不直接视为无缺陷模板。

发现问题后调整文案、尺寸或布局，重新生成计划并重复 validate、preview 和看图。visual.text-overflow 提供问题节点和溢出方向，但没有警告或结构校验通过，都不能代替视觉验收；判断语义和孤字换行仍需 agent 检查。

## 正交路径、泳道和组合

流程图、架构图、UML 类图使用自动正交路径，只有需要指定路径时才写入水平或垂直折点。先结合节点位置规划整条路径，再确定端口和折点；避免逐条边各自选择局部最短路，却使整体线路难以辨认。

流程图按主流程方向选择端口：横向普通顺序边默认右出左入，纵向默认下出上入；分支、回路和跨泳道交接可按局部关系选择显式端口。分配端口时统筹该节点的所有入边和出边，尽量让正常推进、异常出口与退回路径各自容易辨认；不强制每类关系独占一侧。validate/plan 的 `workflow.port-direction` 是非阻断提示，每条提示都要修正或确认是必要的例外，并结合预览自检；不要求为了消除提示机械改口。

为长回路和交接线预留清晰通道，优先利用主干外围、泳道边缘或明确空白区，避免反复穿越主干。多条边可共享通道，但要保留可追踪的来源、方向和箭头，不能把独立路径画成不存在的业务汇合。允许有理由的交叉或绕行，不为追求零交叉而大幅拉长路径。

分支标签靠近判断出口或容易辨认的线段，避开转角、交叉、节点边缘和拥挤区；长路径的标签不机械放在全线中点。节点移动或路径调整后，重新核对标签所指的分支。

流程图、架构图和 UML 类图的普通节点默认只使用上、下、左、右四个端口，每侧中点一个。同一端口可供多条连线进入或离开，起点等有方向限制的节点遵循各自的领域规则。只有图表语义确实需要独立接点时才增加端口。UML 时序图的消息按参与者生命线和事件顺序连接。

泳道默认用于流程图和 UML 类图。架构图使用架构层组织职责边界，旧架构图中的泳道继续兼容。以泳道标题条目的稳定 ID 为键，在 swimlane 的 data.laneMembers 记录成员节点 ID 数组。节点位置必须落在对应泳道正文区，节点的 Frame、流程和架构层关系分别保留。组合成员需要处于同一泳道，或均未分配。UML 时序图通过参与者和组合片段表达分区。

架构连线按关系语义选择线型：dependency 为虚线开放箭头（依赖方指向提供方），flow 为实线实心箭头（发送方指向接收方）；两种语义均可用于层间或模块间。层间关系独立绘制，沿容器外围，默认线宽 2.5；模块间默认线宽 1.5。不要将层与模块混接，或按层间/模块间机械决定实虚线。图例说明方向和关系，说明文字可放在独立 card 中，卡片不参加业务布局。
